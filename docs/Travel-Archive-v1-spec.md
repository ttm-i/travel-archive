# Travel Archive 初版仕様書

## 0. 文書情報

- 文書名: Travel Archive 初版仕様書
- 対象: iPhone向け個人用PWA
- 状態: 初版開発用の確定仕様
- 保存方針: 端末内保存。通常利用時に外部通信を必要としない
- アプリ名: Travel Archive（仮称。実装前に変更可能）

## 1. 目的

日本国内の旅行を、旅行、都道府県、スポット、写真の関係を保ったまま記録し、後から地図・旅行・都道府県の3方向から閲覧できる個人用アーカイブを作る。

同じスポットを複数の旅行で訪れた場合はスポットを重複作成せず、同一スポットへの複数の訪問として管理する。

## 2. 初版の基本方針

- iPhoneのホーム画面から起動するPWAとする。
- 初回導入とアプリ更新を除き、すべてのアプリ機能をオフラインで利用できるようにする。
- 旅行情報、カテゴリ、座標、写真、設定はIndexedDBに保存する。
- サーバーへのユーザーデータ送信、アカウント登録、クラウド同期は行わない。
- データ消失に備え、写真を含む完全バックアップと復元を提供する。
- 地図は日本国内に限定し、道路や店舗情報を持たない県境中心の地図とする。
- 操作はiPhoneの縦画面と片手操作を優先する。
- 開発は段階ごとに停止し、利用者によるiPhone実機確認を経て次に進む。

## 3. 初版の対象外

- 海外の旅行と海外座標
- 道路、建物、鉄道路線、店舗名を含む一般的な地図
- 住所・施設名からの検索および逆ジオコーディング
- GPSによる現在地取得
- クラウド保存、複数端末同期、共同編集
- 旅行経路、移動手段、時刻表、旅程表
- 自動バックアップ
- SNS共有、一般公開、コメント、評価
- 既存データを残したまま別バックアップを合流する復元

## 4. 推奨技術構成

Fashion Archiveで確認済みの構成を基礎とし、別プロジェクトとして実装する。

| 用途 | 技術候補 |
| --- | --- |
| UI | React + TypeScript + Vite |
| PWA | vite-plugin-pwa + Workbox |
| 端末内データ | IndexedDB |
| IndexedDB補助 | Dexie.js |
| 地図 | MapLibre GL JS |
| 地理判定 | ローカルGeoJSON + point-in-polygon処理 |
| バックアップ | ZIP.js |
| テスト | Vitest + Testing Library + fake-indexeddb |
| 配信 | 静的ホスティング。アプリ本体のみを配信する |

外部の地図タイル、検索API、画像配信APIには依存しない。

## 5. 用語とデータの考え方

### 5.1 旅行

連続する開始日から終了日までの一回の旅行を表す。

### 5.2 スポット

名称、座標、都道府県を持つ場所そのものを表す。同じスポットを再訪しても新しいスポットは作らない。

### 5.3 訪問記録

旅行とスポットを結ぶ関係を表す。一つの旅行内で同じスポットは一つの訪問記録として扱う。

写真は訪問記録に紐づける。これにより、同じスポットでも旅行ごとの写真を区別できる。

### 5.4 メイン画像

- 訪問記録ごとに、その旅行内で表示するメイン画像を持てる。
- スポットには、全訪問の写真から選ぶ代表画像を持てる。
- スポット代表画像が未指定の場合は、最初に登録された有効な写真を使用する。

## 6. 機能要件

### 6.1 旅行の登録・編集

以下を登録する。

- 旅行名: 必須
- 同行カテゴリ: 1件以上。複数選択可能
- 開始日: 必須
- 終了日: 必須。開始日以降
- 訪問した都道府県: 1件以上。複数選択可能
- スポット: 1件以上

開始日と終了日が同日の旅行も登録できる。

旅行作成途中の入力は下書きとして端末内に保持し、画面を閉じても再開できるようにする。

### 6.2 同行カテゴリ

- 利用者がカテゴリを作成、名称変更、並べ替え、削除できる。
- 例: 一人、家族、友人、パートナー、職場
- 一つの旅行に複数カテゴリを設定できる。
- 使用中のカテゴリを削除する場合は、対象旅行数を示して確認する。
- 削除後は対象旅行からカテゴリの関連だけを外し、旅行自体は削除しない。

### 6.3 スポットカテゴリ

- 利用者がカテゴリを作成、名称変更、並べ替え、削除できる。
- 例: 観光、食事、宿泊、買い物、移動
- 一つのスポットに設定できるカテゴリは0件または1件とする。
- 使用中のカテゴリ削除時は、未分類にするか別カテゴリへ変更する。

### 6.4 スポットの新規登録

以下を登録する。

- 名称: 必須
- 緯度・経度: 必須
- 有効都道府県: 必須
- 写真: 初回登録時に1枚以上必須
- スポットカテゴリ: 任意

座標は日本国内として扱える範囲のみ保存できる。境界の概算チェックに加え、都道府県ポリゴンによる判定を行う。

### 6.5 座標指定

座標指定方法は次の2種類とする。

#### 地図から選択

- 都道府県境、海岸線、既存スポットを表示する。
- 地図をタップすると候補位置へ移動する。
- 選択後は画面中央の固定照準に対して地図を移動・拡大し、細かく調整できる。
- 確定前に緯度・経度を小数点以下5桁で表示する。
- 確定前に自動判定された都道府県を表示する。

#### 座標を直接指定

- 緯度と経度を別々に入力する。
- 日本国内では負数を使わない前提とする。
- 緯度は `整数2桁 . 小数5桁`、経度は `整数3桁 . 小数5桁` の分割入力とする。
- 小数点は画面に固定表示し、利用者に入力させない。
- 各欄はiPhoneの数字キーボードを表示する。
- 全角数字は半角へ自動変換する。
- 小数部が5桁未満の場合は、確定前に不足を示す。勝手な0補完はしない。
- `35.68124, 139.76712` など2座標をまとめて貼り付ける操作も提供する。
- 空白、全角カンマ、日本語の区切り表記を可能な範囲で解析する。
- 入力後は地図プレビューで位置を確認してから確定する。
- 保存値は小数点以下5桁に丸める。

入力例:

```text
緯度  [35] . [68124]
経度 [139] . [76712]
```

### 6.6 都道府県判定

- 座標と都道府県境GeoJSONを使い、端末内で判定する。
- 自動判定結果と実際に採用した都道府県を別々に保存する。
- 判定不能時は、その旅行で選択済みの都道府県から手動選択する。
- 自動判定と異なる都道府県を採用する場合も、旅行で選択済みの都道府県に限る。
- 座標が旅行の都道府県外だった場合は、座標を修正するか、その都道府県を旅行に追加するよう案内する。
- 手動指定を解除して自動判定に戻せる。

### 6.7 既存スポットの再利用

- 旅行に登録済みの都道府県ごとに既存スポットを検索・選択できる。
- 名称検索と一覧からの選択を提供する。
- 座標が近い候補は表示するが、自動統合しない。
- 選択すると、新しいスポットではなく新しい訪問記録を作成する。
- 再訪時の写真追加は任意とする。
- 既存スポットの名称や座標を編集すると、参照するすべての旅行に反映されることを明示する。

### 6.8 写真

- 初回スポット作成時に1枚以上登録する。
- 一つの訪問記録に複数枚登録できる。
- 写真の追加、削除、並べ替え、メイン画像指定ができる。
- iPhoneで撮影・選択した画像の向きを補正する。
- 表示用画像と一覧用サムネイルを生成してIndexedDBへ保存する。
- 保存前に適切な寸法と品質へ圧縮し、端末容量とバックアップ容量を抑える。
- スポット詳細では全訪問の写真を旅行単位でまとめて表示する。
- サムネイルまたは写真を選ぶと全画面ビューアを開き、左右スワイプ、ピンチ拡大、ダブルタップ拡大で閲覧できる。
- 全画面ビューアではサムネイルではなく、端末内に保存した長辺最大2048pxの表示用画像を使用する。
- 初版では撮影時の無圧縮・原寸ファイルは保持せず、端末容量とバックアップ容量を優先する。
- 旅行の表紙は、旅行に属する登録画像またはカメラロールの表紙専用画像から選択できる。
- 旅行一覧と旅行詳細は同じ元画像を使用し、それぞれの表示比率に合わせた位置と拡大率を個別に保存する。
- 表紙に使った登録画像が削除または旅行から切り離された場合は、既定表示へ戻す。

### 6.9 日本地図

- 道路や地名を表示せず、日本の海岸線と都道府県境を表示する。
- 訪問済み都道府県に色を付ける。
- ピンチ操作による拡大縮小、ドラッグ移動を可能にする。
- 訪問済み都道府県を選択すると、その都道府県が画面に収まるよう拡大する。
- 日本全体や地方を眺める低倍率ではピンとクラスタを表示せず、都道府県の着色を優先する。この間は「拡大するとスポットが表示されます」と案内する。
- ピンを表示し始める倍率は、設定タブのスライダーで広域表示から「かなり近づいてから」まで調整できる。設定範囲は地図倍率4.0〜10.0、刻みは0.2、初期値は5.2とし、選択は端末内およびバックアップに保存する。
- 一定倍率以上へ拡大した後、その範囲に属する登録スポットを橙色の丸いピンで表示する。見た目を小さく保ちつつ、タッチ領域は44px以上とする。
- 密集したピンは深緑色のクラスタにまとめ、中央に所属スポット件数を表示する。クラスタリングには現在倍率の画面座標を用い、クラスタ内の最大距離を制限して数珠つなぎによる過度な集約を防ぐ。同条件ではスポットIDによる固定順序で同じ結果を返す。
- クラスタの表示位置は、所属スポットの画面上の中心に最も近い実在スポットの座標とし、実在しない中間地点には置かない。元のスポット座標は変更しない。
- クラスタを選択すると、所属スポットの広がりから分離に必要な倍率と中心を算出して段階的に拡大する。最大倍率でも分離できない同一座標または極端に近いスポットは、一覧から選択できる画面を表示する。
- ズーム操作中はクラスタ構成を固定し、操作終了後に再計算することでちらつきを防ぐ。地図は北を上に固定し、回転と傾斜を行わない。
- スポット詳細から地図を開いた場合は、地図データの読み込み完了前も対象指定を保持し、対象地点を中心としたある程度広い画角へ移動して対象ピンを最初から表示する。対象スポットはクラスタから除外し、橙色の中心と深緑色の輪郭を持つ選択中ピンとして、通常ピンの表示開始倍率にかかわらず表示する。地図を操作した後もクラスタと同じ塗りには変更しない。
- スポット名は地図上へ常時重ねず、ピン選択後の情報欄に表示する。
- ピン選択時は、画面下部にスポット名、代表画像、カテゴリを表示する。
- 選択中のスポットから都道府県ページまたは旅行ページへ移動できる。
- 複数旅行で訪問済みの場合は旅行を選択するシートを表示する。

#### 6.9.1 地図の絞り込み

- 地図タブに「絞り込み」ボタンを置き、iPhoneでは画面下部から開くシートで条件を指定する。
- 条件は「旅行期間」と「同行カテゴリ」とする。
- 旅行期間は「すべて」「今年」「過去1年」「期間指定」を選べる。期間指定は旅行登録と同じ一つのカレンダーUIで開始日と終了日を選ぶ。
- 旅行の期間が指定期間と1日でも重なれば対象とする。判定は `旅行開始日 <= 指定終了日` かつ `旅行終了日 >= 指定開始日` とする。
- 同行カテゴリは複数選択でき、選択したいずれか一つを含む旅行を対象とする。未選択はすべての同行カテゴリを意味する。
- 期間と同行カテゴリを両方指定した場合は、両方の条件を満たす旅行だけを対象とする。
- 条件に合う有効な旅行から参照されるスポットだけを表示し、都道府県の着色、ピン、クラスタ、訪問回数、旅行選択肢も条件内の旅行に限定する。
- 同じスポットが条件内の複数旅行に含まれても、地図上のピンは一つとする。
- ピンの情報欄には「条件内の訪問回数」を表示する。全訪問回数と異なる場合は `条件内2回 / 全3回` のように区別する。
- スポット詳細へ移動した後は、そのスポットの全写真・全旅行を表示する。絞り込みは地図上の探索だけに適用する。
- 適用中はボタンに条件数を表示し、地図上部に期間・同行カテゴリの要約チップと「解除」を表示する。
- 結果が0件の場合も地図は操作可能とし、「条件に合う記録はありません」と解除操作を表示する。
- 条件は地図から詳細画面へ移動して戻った場合、および別タブへ移動して戻った場合に保持する。アプリを再読み込みした場合は「すべて」に戻す。
- 絞り込み条件は閲覧中だけの状態とし、IndexedDB、バックアップ、未バックアップ変更件数には含めない。

### 6.10 都道府県ページ

- 都道府県名を表示する。
- その都道府県のスポット画像またはカメラロール画像から表紙を1枚選び、一覧サムネイルと詳細タイトルで共通使用できる。
- 一覧サムネイル用と詳細タイトル用は、それぞれの比率に合わせて表示位置と拡大率を個別に調整できる。
- 登録画像を削除した場合は既定表示へ戻す。
- スポット一覧に名称と代表画像を表示する。
- 初期順は名称順とし、将来の並べ替え拡張を妨げない構造にする。
- スポットを選択すると共通のスポット詳細画面へ移動する。

### 6.11 旅行ページ

- 旅行名、期間、同行カテゴリ、訪問都道府県を表示する。
- スポット一覧に名称と、その旅行でのメイン画像を表示する。
- その旅行に写真がない再訪スポットではスポット代表画像を使用する。
- 都道府県名から都道府県ページへ移動できる。
- スポットを選択すると共通のスポット詳細画面へ移動する。

#### 6.11.1 旅行タブのスポット検索

- 旅行一覧の上部に、スポット名称の検索欄とスポットカテゴリの絞り込みボタンを置く。
- 名称検索は前後空白を除去し、全角・半角を正規化したうえで部分一致とする。大文字・小文字は区別しない。
- スポットカテゴリは複数選択でき、選択したいずれか一つに属するスポットを対象とする。「未分類」も独立した選択肢として用意する。
- 名称とカテゴリを同時に指定した場合は、同じ一つのスポットが両方の条件を満たす必要がある。旅行内の別々のスポットが各条件を満たすだけでは検索結果に含めない。
- 条件を満たす有効なスポットとの有効な訪問記録を一つ以上持つ旅行だけを一覧に残す。
- 検索結果でも旅行の並び順は開始日の新しい順を維持する。
- 各旅行カードには一致したスポット数と、先頭から最大3件のスポット名を表示し、その旅行が表示された理由を分かるようにする。
- 旅行カードを選択した後の旅行詳細では、その旅行の全スポットを表示する。検索条件は旅行一覧の発見操作だけに適用する。
- 旅行詳細から戻った場合、および別タブへ移動して戻った場合は検索条件とスクロール位置を保持する。アプリを再読み込みした場合は解除する。
- 条件適用中は該当旅行数と「解除」を表示する。0件の場合は、新規旅行作成ではなく条件解除を第一操作として案内する。
- 削除済みの旅行、訪問記録、スポットは検索対象に含めない。
- 検索条件は閲覧中だけの状態とし、IndexedDB、バックアップ、未バックアップ変更件数には含めない。

### 6.12 スポット詳細

- スポット名
- スポットカテゴリ
- 代表画像と全画像
- 訪れた旅行一覧
- 採用中の都道府県名
- 都道府県内地図とスポット位置を示す一つのピン
- 編集操作

スポット編集では名称、カテゴリ、座標をスポット共通情報として変更できる。都道府県は共有旅行との整合性を守るため変更不可とする。写真は訪問記録単位で管理し、旅行選択欄で表示・追加・並べ替え・削除の対象を切り替える。旅行詳細から遷移した場合はその旅行を、それ以外は開始日が新しい関連旅行を初期選択する。

旅行一覧から旅行ページ、都道府県名から都道府県ページ、地図から日本地図ページへ移動できる。

### 6.13 削除とゴミ箱

- 旅行は直ちに完全削除せず、ゴミ箱へ移動する。
- 共有スポットはスポット自体を全旅行から削除せず、旅行詳細からその旅行との訪問関係だけを外す。
- ゴミ箱から復元または完全削除できる。
- 旅行削除時は訪問記録をゴミ箱対象に含めるが、別旅行から参照されるスポットは削除しない。
- 訪問関係を外す操作は、スポット詳細の「訪れた旅行」の全行に同じアイコンで表示する。
- 最後の訪問関係を外す場合は、その旨を確認してスポットもゴミ箱へ移動する。
- 完全削除後の復旧はバックアップからのみ可能と案内する。

### 7.3 iPhone表示規則

- 縦画面を主対象とする。
- セーフエリア、ホームインジケータ、ノッチを考慮する。
- 主要タップ領域は44px相当以上とする。
- 地図上の重要操作は画面下部へ置く。
- モーダルよりも、下から開くシートまたは独立画面を優先する。
- 入力画面では未保存の内容を誤って失わないよう警告する。

### 7.4 画面遷移と写真の動き

- 一覧から詳細へ進む場合は、本文を右から左へ短く移動させながら薄くフェードする。ただし移動量と透明度は控えめにし、旅行記録をめくるような落ち着いた動きにする。
- 戻る場合は進む場合と逆方向に動かし、画面階層を視覚的に伝える。
- 下部4タブの切り替えは、階層移動と混同しない150ms程度のごく短いフェードと上方向3px以内の動きにする。選択タブのアイコンと上線を静かに強調し、下部タブ自体は動かさない。
- 全画面写真ビューアはフェードと軽い拡大で開き、前後の写真は操作方向に合わせて左右から切り替える。ボタンとスワイプで同じ動きを使う。
- 通常の画面遷移は180〜240ms程度とし、操作を妨げない範囲に抑える。
- 下部タブ切替ではブラウザの全画面スナップショット型アニメーションを使用せず、アプリ本文のCSSアニメーションだけを使用する。これにより固定ヘッダー、セーフエリア、下部タブ、WebGL地図の描画欠けを避ける。
- `prefers-reduced-motion`が有効な場合は、移動や拡大を実質的に無効化する。

## 9. 保存・オフライン仕様

- IndexedDBをユーザーデータの正本とする。
- Service Workerはアプリ本体、地図ライブラリ、フォント、アイコン、都道府県GeoJSONを事前キャッシュする。
- 通常操作中に外部ネットワーク要求を発生させない。
- オフライン時も登録、編集、削除、地図、写真、バックアップ、復元を利用できる。
- アプリ更新時は更新可能であることを表示し、利用者が「更新する」を選択した時だけ反映する。
- 更新中もIndexedDBを削除しない。
- 初回インストール直後に、必要な静的ファイルがキャッシュ済みであることを確認できる状態表示を設ける。

## 10. バックアップ・復元

### 10.1 完全バックアップ

- 旅行、スポット、訪問記録、カテゴリ、設定、写真を一つのZIPへまとめる。
- ファイル名は `TravelArchive_Backup_YYYYMMDD_HHmm.zip` とする。
- manifestにアプリ名、形式バージョン、作成日時、件数、画像数を保存する。
- 地図データとアプリ本体はバックアップに含めない。
- 作成後に最終バックアップ日時を保存する。
- 前回バックアップ後に変更がある場合は設定画面などで知らせる。
- 写真量が多く、端末で安全に作成できない場合は処理前に警告する。

### 10.2 復元

- ZIP選択後、適合するバックアップか検証する。
- 復元前に作成日時、旅行数、スポット数、写真数を表示する。
- 利用者の最終確認後、現在のユーザーデータをバックアップ内容で全置換する。
- 検証に失敗した場合は現在のデータを変更しない。
- 復元途中に失敗した場合も、可能な限り元データを保持する一時領域方式を採用する。
- 新しい形式のバックアップを古いアプリで無理に読み込まない。

## 11. PWA・プライバシー

- manifestはstandalone表示と縦画面優先を設定する。
- アプリアイコン、起動画面色、テーマ色を用意する。
- 写真、旅行情報、座標は外部送信しない。
- 静的ホスティング上にユーザーデータを保存しない。
- ブラウザまたはiPhoneのWebサイトデータ削除でデータが失われることを明記する。
- 定期的なZIPバックアップと「ファイル」またはiCloud Driveへの保管を案内する。

## 12. エラー・案内表示

- 保存容量不足
- 画像読込・圧縮失敗
- 座標形式エラー
- 日本国内または都道府県を判定できない座標
- 旅行の都道府県とスポットの都道府県の不整合
- バックアップ作成失敗
- 復元ファイル不正またはバージョン非対応
- オフライン利用準備が未完了
- アプリ更新可能

エラー文は利用者が次に行う操作を明示し、内部用語や例外内容をそのまま表示しない。

## 13. 初版の受入条件

- iPhoneのホーム画面からstandaloneで起動できる。
- 機内モードでアプリを再起動し、主要画面を表示できる。
- 機内モードで旅行、スポット、カテゴリ、写真を登録・編集できる。
- 複数都道府県と連続日付の旅行を登録できる。
- 地図選択と小数点以下5桁の直接入力で座標を保存できる。
- 座標から都道府県を自動判定し、条件内で手動変更できる。
- 同一スポットを複数旅行へ関連付けられる。
- 日本地図、旅行、都道府県の3方向からスポットを閲覧できる。
- 密集地点をクラスタ表示できる。
- ピンから写真、都道府県、関連旅行へ移動できる。
- 写真を含む完全バックアップを作成し、全削除後に復元できる。
- アプリ更新後もIndexedDBのデータが維持される。

## 14. 確定済みの判断

- 座標指定は地図選択と直接入力の2方法のみ。
- 直接入力は小数点以下5桁を必須とし、数字キーボード向けの分割UIを使う。
- 単一選択・複数選択のボタンは選択時も幅を変えず、濃い背景色と白文字で状態を示す。選択状態は `aria-pressed` でも提供し、選択のためだけのチェックマークは表示しない。
- 現在地取得、住所検索、施設名検索は初版に含めない。
- 同行カテゴリは複数選択可能。
- スポットカテゴリは任意で1件。
- 初回スポット作成時は写真必須。再訪時の追加写真は任意。
- 写真は訪問記録に紐づけ、スポット詳細では全訪問分を集約する。
- 復元は既存データとの統合ではなく全置換。
- 通常利用は完全オフラインとし、外部地図サービスを使わない。

## 15. 実装直前に利用者と確認する事項

機能仕様として未確定の必須項目はない。画面モック段階で次の表現だけを確認する。

- 正式なアプリ名
- 全体の色・書体・写真カードの雰囲気
- 日本地図で訪問済み県に使う色
- 座標指定画面の分割入力と地図微調整の操作感
